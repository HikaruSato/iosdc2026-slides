# iOSDC Japan 2026 slides

「映像変換サーバーなしでiPhone端末内でHLSを生成してライブ配信」の発表スライドです。
全68枚（本編63枚・末尾の補足5枚）で、40分想定です。通常は本編を話します。
Optional detailは時間超過時だけの予備であり、省略を前提にした時間配分ではありません。
ライブデモ成功時は代替説明5枚（14〜18ページ）だけを省略し、58枚とデモで進めます。失敗時はライブ操作を切り上げ、代替5枚で説明します。
最初に、撮影後のアップロードを待たずにURLで共有したいという動機と、
Apple公式サンプルをきっかけにiPhone内でHLSを生成できた経緯を説明します。続いて、短い動画ファイルと更新されるplaylistによって
HLSがライブ配信になる仕組みを説明し、その全体像へ今回の構成を当てはめたあと、`../iosdc2026HLSSample` を使い、
iPhoneでHLSを生成してMacのHTTPサーバーへPUTし、保存された `init.mp4`、`.m4s`、
`playlist.m3u8` をViewerで追従再生するデモを行います。その後、`AVCaptureSession`、DataOutput、
`AVAssetWriter`、iOS 26以降のSampleBufferReceiver、Writer delegateをどう接続するとHLS用Dataを取り出せるかを、
約2秒のfragment生成を含めて順番に説明します。時刻の扱いはApple公式サンプルの方針を参考にしており、
本編では「映像と音声を同じ量だけずらし、時間差を保つ」という時間軸の図1枚にまとめています。
最後に、保存できたsegmentだけをplaylistへ公開する順序と、
公開サンプルのMac保存をMomentNowのS3・署名付きURL・commit・CloudFrontへ置き換えた構成を扱います。

品質・ビットレートの選択、アップロード失敗時のリトライ、キャッシュ制御は必ず話します。
SafariとAVPlayerでの再生確認にも、デモ代替ページを省略する場合を含めて触れます。
デモの前に写真への追加権限を許可します。配信停止後は保存成功の表示を待ち、写真アプリで保存動画を再生します。
公開サンプルも撮影データを2つのWriterへ渡し、配信用H.264（720×1280）と保存用HEVC（1080×1920・5 Mbps、AAC 96 kbps）を並行生成します。
Sampleは停止後に写真へ自動保存し、MomentNowは元動画uploadと設定に応じた写真保存を行います。
写真保存とHLSのENDLIST公開はそれぞれの結果を確認します。写真保存が失敗した場合はアプリから再試行します。
デモ直前の権限ページで、カメラ・マイク・写真への追加と、同じLANのMacへ接続する際のローカルネットワーク権限を説明します。
写真は追加のみを要求し、Sampleでは配信開始の必須条件です。用途を記すInfo.plistキーと権限要求APIはノートにまとめています。
AudioSessionの設定はCaptureSessionのページのノートで補足します。画面回転、詳細なencode設定、guard条件などのOptional detailは、時間超過時に限って省略できる予備です。
Writer側のCMSampleBufferのdropは参考ノートに残し、生成済みsegmentの送信待ちと区別します。
サンプルには送信待ちの明示的な上限がなく、上限と超過時の停止判断は今後の改善です。
実durationの反映ではSampleとMomentNowの現状を区別します。公開順は実際の動作検証で起きた問題と、生成時の番号順へ並べる対策を話します。欠番を待つ未実装の改善案は公開順ページの参考ノートだけに残します。
commit APIはMomentNowが選んだ責務配置であり、HLS必須のAPIとは扱いません。
時間軸の独立章は設けず、Writerの開始処理、10秒の余白とAAC priming、時刻の計算式、コピー処理のコードは
発表終了後の補足（64〜68ページ）にまとめています。

## 設定値の理由

[MomentNowの開発記事](https://zenn.dev/hs7/articles/080eac650f65ba)と現行コードを照合し、設定の理由を説明する2枚（27・45ページ）を本編に残しています。
記事が明示する採用理由、Apple等の一次資料が説明する性質・推奨、今回の具体的な設定例を分けて話します。出典と詳しい注意点は各ページのノートにあります。

- 配信H.264と保存HEVC、720pと1080pの使い分け。
- 約2秒segmentの待ち時間とHTTP回数のトレードオフ。IDRの約2秒推奨とsegmentの約6秒推奨を区別。

入力形式、圧縮profile・frame順序の注意点と出典は映像設定（32ページ）、音声設定の詳細はReceiver接続（34ページ）の参考ノートに残しています。音声もAAC設定のInputとReceiverを用意することは画面に残しています。

600というtimescale、10秒の開始位置、リトライの回数・待ち時間、cacheの0秒／365日も、該当ページやノートで意味を説明します。
記事の約2.7 Mbps・音声93 kbps・30 fpsは当時の出力例です。現行コードの設定値や30 fps固定の実装として扱いません。
具体的なbitrateを一般推奨値や比較検証済みの最適値とは説明しません。修正後の原稿で通し練習を行い、発表時間を確認します。

bitrateのデータ量への換算ページは設けず、品質選択（31ページ）で、値を上げると画質に使えるデータ量と通信量が増えることだけ補足します。平均値の目標と実測値の違いはノートに残しています。
設定説明の入口（27ページ）で、初期設定を継続している値が多いことを明示します。
MomentNowは想定ほど利用が広がらず、実ユーザーの声を設定の見直しへ十分につなげられていません。
61ページの振り返りでもこの点を率直に話し、実装時の動作確認と、利用実績・ユーザー評価に基づく最適化を区別します。
少人数・短時間・単一品質は想定した用途であり、利用者への適合性を本番の実績で十分に検証したという結論にはしません。
最後の「ありがとうございました」（63ページ）には、サンプルコードと開発記事のURLを掲載しています。

## 図解の見せ方

HLSを知らないiOSエンジニア向けに、図で役割・処理順・並行処理を確認してから要点コードを示します。
リハーサルを踏まえ、重複する説明や運用機能の詳細を削除・統合しています。HLS入門は3種類のファイル、最初の取得、playlist更新の流れに絞っています。
Receiverの役割は接続コード、appendImmediatelyは2つのWriterへの入力図、撮影中のData出力はWriter delegate、非同期送信と送信待ちの注意点は停止処理のノートへまとめています。
Sampleの保存・playlist更新・リトライの後に、MacとS3の比較（54ページ）、公開順の検証と対策（55ページ）、キャッシュ（56〜57ページ）を続けます。commitは保存済みsegmentをplaylistへ反映する処理として短く紹介します。署名付きURLや運用機能の専用ページは戻しません。
品質選択・映像設定（31〜32ページ）、実duration（46ページ）、端末保存と設定理由（26〜27ページ）は内容を維持しています。
段階説明は別ページにしているため、Slidevのクリック操作なしでもPDF上で順番に追えます。

- 配信用HLSは青、保存用MP4は緑。名称も併記し、色だけに依存しません。
- 時間軸は原則左から右。処理時間の模式図と実出力例を区別します。
- 図とコードは同じ責務・名称で対応づけます。要点コードは抜粋と明示し、細部はノートへ残します。
- 公開順の図は「完了順に並べた場合」と「生成時の番号順に並べる対策」を対比します。図の番号順は模式例で、実測ログそのものではありません。
- 停止処理は59〜60ページ。Recorderの現在の終了順と、HTTP送信・写真保存の並行処理を分けます。
- Sample・MomentNowを区別します。欠番を待つ改善案は読み上げない参考ノートへ分けます。

図はHTML/CSSで編集できます。共通の図用スタイルは `styles/diagrams.css` にあります。
デモの13ページには、撮影データがHLS配信と写真保存へ分かれる全体図を掲載しています。この図は `components/SampleDataFlow.vue` のSVGで編集できます。

## スピーカーノートの使い方

全68ページのノートを、次の区分に統一しています。

- **話す**：そのまま話せる原稿。図・コードの注目点と、次の話題へのつなぎを含みます。
- **操作・進行（読み上げない）**：デモ操作、代替ページへの切り替え、練習用チェックポイント。必要なページだけにあります。
- **参考・質問対応（読み上げない）**：詳しい設定理由、技術的な注意点、出典。発表原稿へ機械的に足さず、質問時や実装時に参照します。

設定値が最適化済みではないこと、単一品質であること、時刻調整を外した検証の条件、送信待ちの上限が未実装であることは、「話す」にも残しています。欠番を待つ改善案の説明は本編では行いません。
デモ成功時は14〜18ページを省略して19ページへ進みます。64ページ以降は補足です。

## 通し練習

ノートのTiming checkpointはすべて練習用の仮目安であり、実測済みの所要時間ではありません。
デモ込みで35〜37分を目標に通して話し、実測後にチェックポイントを調整します。
40分に収まるかは枚数だけで判断せず、図を理解する間やコードの説明時間も含めて確認します。
デモが成功する場合と、失敗して代替説明へ切り替える場合の両方を練習します。
